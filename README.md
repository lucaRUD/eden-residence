# Eden Residence

Residential presentation website built with Astro, strict TypeScript, Tailwind CSS v4, Quicksand and GSAP/ScrollTrigger. Romanian is at `/`; English is at `/en/`. The project is prepared for a manually initiated Vercel preview. WordPress integration, inquiry processing and the final domain launch remain deferred.

The client-supplied national-first passive-building claim is visibly provisional and requires verification before public launch. Apartment details and contact information remain pending. Both homepages retain `noindex, nofollow`.

## Develop

Use Node.js 24.x, npm and Git. The project has been checked with Node 24.22.0; `package.json` also selects this major version on Vercel. PowerShell examples use `npm.cmd` to avoid execution-policy restrictions on `npm.ps1`; other shells can use `npm`.

For a fresh checkout, run `npm.cmd ci` once. Do not reinstall dependencies for routine frontend changes.

```powershell
npm.cmd run dev
```

Open Astro's printed URL, normally <http://localhost:4321/> or <http://localhost:4321/en/>. Stop with Ctrl+C. The default server is local only.

## Verify and preview

```powershell
npm.cmd run check
npm.cmd run build
npm.cmd run preview
```

`check` performs Astro/TypeScript diagnostics; `build` writes static output to ignored `dist/`. Production preview serves that output locally and does not deploy it. Use focused browser checks for changed behavior. Follow [AGENTS.md](AGENTS.md) for testing, artifact and completion-response rules.

The useful development-only design-system page is at `/design-system/` (Romanian) or `/design-system/?lang=en` (English). It uses demonstration content and shared components. It is excluded from production builds and production preview.

## Environment and production

`.env.example` reserves `WORDPRESS_URL` for future build-time use. A real `.env` is unnecessary for current development: builds do not contact WordPress. Keep secrets out of `PUBLIC_` variables, Git and static output. Production WordPress and hosting require separate approval before modification.

## Shareable Vercel preview

The site uses Astro's static output; no SSR adapter or runtime environment variables are required. `vercel.json` selects Astro, installs from the committed lockfile with `npm ci`, runs `npm run check && npm run build`, and publishes only `dist/`. Node.js is pinned to 24.x. All pages retain `noindex, nofollow`; this is a review deployment, not the final domain launch.

1. Review `git status` and `git diff`, then manually commit the intended changes, including `public/favicon.png`, configuration and the lockfile. Keep `.env`, dependencies, build output and credentials excluded.
2. Create an empty **private** GitHub repository. Add its URL as the Git remote (or verify the existing remote), then push the current `main` branch yourself.
3. In Vercel, choose **Add New → Project**, authorize access to that repository and import it. Use the repository root, the **Astro** preset and **Node.js 24.x**; build/output settings come from `vercel.json`. Leave environment variables empty.
4. Deploy when ready and share the generated `*.vercel.app` URL. Leave `edenresidence.ro` unattached. Check the project's Deployment Protection settings against the intended reviewers' access.

The first `main` deployment is called Production by Vercel even though it is only this website's review preview. Later branch pushes produce Vercel Preview Deployments. The development-only routes (`/design-system/`, `/dev/cinematic-hero/`, `/dev/cinematic-car/`, `/dev/architectural-story/`) are never generated by a production build. GitHub repository privacy does not itself restrict access to the deployed website.

See the [official Astro Vercel deployment guide](https://docs.astro.build/en/guides/deploy/vercel/). No commit, push or deployment is performed by these instructions.
